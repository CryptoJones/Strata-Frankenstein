# Upstream sync for CUDA V100: 2026-10-19

## Source and scope

The upstream source is commit `3d1fb480`.
The fork baseline is commit `ebd2f7ad`.
This branch imports shared engine and server changes. It does not import the
complete upstream product. Use CUDA 12.8 and compute capability 70 for V100.
CUDA 13 cannot compile this target.

## Integration rules

Keep the fork's Volta kernel selection, prompt staging, and resident routing.
Keep the pipeline K/V growth path and its memory limits.
Keep the RAM and disk conversation caches, shared prefixes, archive append
reuse, and answer-only idle prefill.
Keep the fork's authenticated server and metrics interface.

Import shared CUDA, CPU, model loader, prompt planner, and server fixes with
their required interfaces. A shared source file can contain guarded code for
other GPU types. These guards do not select another backend in the V100 build.
An imported option is not a measured V100 performance improvement.

## Excluded changes

Do not import the desktop application, distribution packages, or their
workflows. Keep the fork's installation overview. Keep the shared
`strata_control` and `strata_cli` Python modules because the server,
installer, and protocol checks import them. Do not import terminal
distribution assets.
Do not import separate AMD, Intel SYCL, or Apple Metal backend changes.
Do not import upstream benchmark output or private runtime settings.
Exclude new standalone timing programs, community benchmark clients, benchmark
corpora, quantization-analysis scripts, and model-development harnesses.
Keep existing fork tools and the production correctness checks.
Exclude the new CLI benchmark command and its benchmark-only control actions.
Keep model calibration and the existing fork benchmark tools.

## Runtime rules

Use a separate configuration with the regular IQ3_S model for PR checks.
Do not install the candidate engine as the daily engine before approval.
After checks, start the daily user service with the matching abliterated
SC117 IQ3_S pack, tokenizer, and model shards. Keep GPU order `[0, 1]`,
`layer_split` `"16"`, and `--pipeline-windows 2`.
