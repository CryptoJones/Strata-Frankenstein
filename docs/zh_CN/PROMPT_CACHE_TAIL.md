# 提示词尾部附近的可选检查点
<a id="optional-checkpoint-near-the-prompt-tail"></a>

`--prompt-cache-tail` 在一次请求接近末尾处最多多保存一个提示词中段的检查点，
位置在批量 prefill（预填充）已经到达的某个边界上。它默认关闭，适用于单 GPU serve，
且要求 `--prompt-cache` 和 `--prompt-cache-every` 取正值。

一个分支可以共享提示词的大部分内容，但在其最终缓存状态之前发生分歧。
如果该分支之前的周期性检查点距离很远，引擎就必须再读一遍这段空隙。这个额外的检查点可以缩小该空隙。
它使用现有的有界检查点缓存；不会再增加一份无界的历史。

尾部是指提示词末尾一个块范围内的第一个块边界，其中的块大小取该块实际是的大小
（`--prefill auto` 的块与 `--prefill N` 不同）。尾部检查点最先被逐出（只保留一个存活，根从不丢弃），
所以在 `--prompt-cache` 已满时它永远不会挤掉一个周期性检查点。

该选项不拆分 prefill 块，也不改变周期性检查点的安排。
它选择提示词末尾一个已配置块范围内第一个完成的批量块，
不含由 `--short-read` 控制的最后那截短后缀。如果那里已经有一个周期性检查点，同样的状态只会被保存一次。
重读诊断和层切分保持其现有行为。

例如，块为 6144 token、检查点间隔为 16384 token 时，
第一个周期性检查点在 18432，下一个会在 36864。
共享 32769 个 token 的分支无法使用后者。在 30720 处的近尾部检查点
可以复用该前缀的更多部分，
而不改变原始提示词的计算方式。收益取决于具体请求和分支位置；它不是普遍的速度提升。

对于 Strata-2080Ti Daily 的检查点网格（checkpoint-grid）补丁来说，这是一个独立的保守替代方案。
该网格通过改变块边界来凑到精确的检查点间隔，并且在本地配对数值门槛上未能通过。本选项
不声称原来的网格补丁已被修复或验证。
